# 臉部模式：自然閉嘴取代皺眉

最新決策採「自然閉嘴巴，短暫維持即可通關」。不採用皺眉、生氣臉、嘟嘴或鼓頰，也不要求先張嘴再閉嘴。沿用既有 Game、自然觀看校正、Camera 教學、個人化設定及非阻斷追蹤處理，手部模式維持停用。

## 自然閉嘴規則

這是「當下姿勢符合」的容易題，並非新的表情變化或開閉循環：

- 原本已閉嘴、從張嘴轉為閉嘴、閉嘴微笑及嘴唇自然輕觸都可成功。不要求咬合、用力抿嘴、眼睛大小或眉部動作。
- 提示出現就開始累積連續有效閉合時間，預設約 300ms。提示前不提前計時，同一障礙只觸發一次。
- 下一個閉嘴障礙允許繼續保持閉嘴，重新累積該題維持時間，不要求在兩題間張嘴。
- 教學確認閉合後直接進入下一課，不使用其他姿勢的「等待解除」要求玩家張嘴。
- 下顎明顯張開、嘴唇有開口或嘴部關鍵點不完整都不通過。無效影格不加時間；恢復後重新確認有效維持，不能把失追期間拼成成功。

### 訊號與尺度

由內唇三組點對 `(13,14)`、`(82,87)`、`(312,317)` 估計開口，取最大間距再除以兩外眼角間的臉部尺度，記為 `lipGap`。檢查嘴角 `(78,308)` 寬度與各點有效性，避免缺少或塌縮的嘴部網格被當成閉嘴。此對應參考 [MediaPipe 官方嘴唇連線](https://github.com/google-ai-edge/mediapipe/blob/master/mediapipe/python/solutions/face_mesh_connections.py)。

閉合必須同時滿足 jawOpen 與 lipGap 上限。低 jawOpen 不代表嘴唇接觸；Landmarks 也只能估計閉合，不能直接量測咬合。閉嘴判斷使用目前影格的嘴部資料，避免濾波仍保留上一個閉合值，將剛張開的嘴判成功。

參數集中於 `FACE_CONFIG`：初始實驗上限 jawOpen 0.18、lipGap 0.025。教學只收集已通過雙重檢查的閉嘴影格，以 P95 加小幅容錯建立 `FaceProfile.closedMouth`，並限制在上述上限內；自然基準若本來張嘴，不會把張嘴狀態學成閉嘴。這些數值是待真人調校的實驗設定，不能宣稱適用所有裝置與玩家。閉嘴不使用表情增量或「降低門檻直到成功」策略。

## 其餘行為保留

自然觀看約 2 秒，記錄舒服看畫面時的角度、表情、尺度與自然雜訊，不要求正對鏡頭、零度角或刻意睜眼。其他動作仍依自然基準與教學有效幅度建立個人觸發／解除值，採主要軸向優先，不以頭部平移代替旋轉。

張嘴仍須產生明顯 jawOpen 變化；微笑仍須嘴角有效上揚，可伴隨張嘴或閉嘴，不要求嘴角對稱。閉嘴不會直接算成張嘴或露齒微笑。睜眼＋抬眉保留原本的共同出力算法，不因本次變更增加互斥限制。模型沒有直接辨識牙齒可見的專用係數，露齒圖示只是教學示範。

其餘姿勢仍使用遲滯、維持時間與有限波動容錯。每種動作分別待命，上一題仍維持轉頭／微笑不會卡住新的獨立動作；相同一般動作需放鬆後才可再做。只有閉嘴牆允許預先維持與連續同姿勢過題。擊破維持 3 次穩定張閉嘴循環，閉嘴題不會代替或降低擊破要求。

正式臉部遊戲仍從提示出現接受有效操作，顯示「動作已完成」後可放鬆，障礙抵達才結算，完成紀錄只對應當前障礙。追蹤失敗不彈窗、不自動暫停、不強迫重新校正，也不取消已完成的障礙。手動／隱藏頁面暫停及全身模式規則維持原狀。

## 真人驗收

1. 重新整理並完成校正。確認第六種穿牆教學是「自然閉嘴巴」，保持原本閉嘴即可完成，不需要先開嘴；成功後直接進入下一課。
2. 在 [診斷頁](FACE_DIAGNOSTICS.md) 選自然閉嘴。先測閉嘴、輕微張嘴、閉嘴微笑：後兩個嘴角狀態可重疊，但嘴唇仍微開時不應通過，即使 jawOpen 很低。
3. 測從張嘴轉為閉嘴、嘴唇輕觸、不同距離／頭部自然角度／位置，仍可有效追蹤時應能維持閉合判定；不要求用力抿嘴或咬牙。
4. 連續閉嘴牆各自計時通過，不在兩題之間張嘴；同一題不可重複得分。短暫遮住嘴巴、臉部失追及恢復不得靠無效資料成功。
5. 回歸張大嘴巴、露齒微笑、睜眼＋抬眉和擊破，確認其他題型仍需自己的有效動作，擊破必須完成完整循環。
6. 記錄嘗試數、成功／誤觸、延遲與舒適度；必要時匯出診斷數值。資料只在本機處理，不需要上傳人臉影像。

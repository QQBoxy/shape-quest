## 1. 目標與專案基線

建立純前端兒童體感跑酷遊戲，透過前鏡頭在本機辨識動作，以 HTML5 Video 與 Canvas 呈現第一人稱自動前進的冒險，使用 GitHub Pages HTTPS 發布。

本文件於規劃階段建立，現已開始 Phase 1 實作。初始檢查時專案僅有 `README.md`，分支為 `main`，遠端為 `https://github.com/QQBoxy/shape-quest.git`；沒有套件、程式、測試及 CI/CD。初始化後已選定 Node.js 24.20.0 並建立程式、測試與工作流程；遠端權限、Pages 設定及手機／平板實機支援仍待驗證。

產品整體需求以原始規格為準，背景美術、影片生成與合成以新增背景規格為目前基準。原始規格保留不改寫；其中動態難度調整接近速度的構想，依新規格改為優先調整出題間隔、組合與複雜度，速度變化另行驗證。本計畫新增的預設值及演算法屬實作起點，需經測試調整。先完成 Phase 1，後續階段只列路線圖。

## 2. Phase 1 範圍與取捨

### 必須交付

- 主畫面、安全空間提醒、開始、全螢幕及 CSS 滿版替代。
- 前鏡頭與 MediaPipe 初始化、載入進度、錯誤提示及重試。
- 鏡像攝影機、骨架、全身入鏡檢查、站姿與動作範圍校正。
- Jump、Duck、左右 Dodge；自動前進，不辨識原地跑步。
- 可循環的合法或原創 MP4 背景，載入失敗不可顯示假成功。
- 先以 Level 1 陽光草原首支候選影片，完成道路／障礙合成、循環、暫停與行動裝置驗證，再擴充素材。
- Canvas 透視障礙、同步放大的動作輪廓、成功與碰撞回饋。
- 判定時間窗、時間序列防抖、回正後重新觸發及一次性結算。
- 三顆愛心、扣血、無敵、基本分數、成功／失敗次數、結算與重新開始。
- 失追自動暫停、恢復倒數、手動暫停及頁面隱藏暫停。
- 預設隱藏攝影機、左下預覽切換、追蹤狀態與 Debug Overlay。
- Vitest、Playwright、手機／平板實機驗收及 Pages 自動部署。

### 階段邊界

Phase 1 使用單一約 60 秒的「原型挑戰」，涵蓋全部三種動作與左右方向。正式 Level 1 含姿勢穿牆，需等待 Phase 2、3，原型不冒充正式 Level 1。

本階段不做 Hole in the Wall、Smash、完整關卡、Boss、智慧隨機、動態難度、連續成功補血或 localStorage 成績保存。不加入後端、帳號、前端框架或繪圖引擎；正式音效、美術與素材切換介面後續處理。

原規格 Phase 4 的暫停、預覽切換及基本裝置相容性，先在 Phase 1 做到公平遊玩的必要程度，再於 Phase 4 擴充與最佳化。

## 4. 預定架構與資料流

檔案依責任逐步建立，不預先產生空殼或通用遊戲引擎。

```text
src/
  main.ts          初始化與組裝
  config.ts        遊戲、辨識、校正與資源參數
  camera.ts        權限、串流、錯誤與釋放
  pose.ts          模型、節流推論、品質與座標轉換
  calibration.ts   入鏡、站姿基準與動作範圍
  actions.ts       姿態特徵、時間序列與動作事件純函式
  game.ts          狀態、時鐘、障礙排程、判定、生命與分數
  renderer.ts      Canvas 透視、輪廓、回饋與畫面合成
  background.ts    單支影片載入、播放狀態、固定速率、暫停與錯誤
  ui.ts            畫面、HUD、控制、滿版與 Debug
  styles.css
public/
  models/          固定模型
  wasm/            對應版本執行檔
  videos/          授權或原創背景
tests/
  unit/            純函式與合成姿態測試
  e2e/             瀏覽器流程與子路徑測試
.github/workflows/deploy.yml
```

資料流：攝影機 → Pose Landmarker → 品質檢查與正規化 → 校正／動作事件 → 遊戲判定 → Canvas 與 DOM。辨識不直接扣血，渲染不直接修改分數；判定核心不依賴 DOM 或真實鏡頭。

背景播放職責由 `background.ts` 管理，`renderer.ts` 負責前景合成；影片管理不可直接控制判定。Camera / Motion Profile 草案先集中於 `config.ts`，通過校正後記錄版本與實際值。正式循環採單一 HTML5 Video 播放離線淡化 MP4；不同場景的切換方式須另行驗證。

姿態附取樣時間、關鍵點及品質；動作事件附類型、方向、時間與唯一識別；障礙附題型、預告時間、碰撞時間與結算狀態。成功、失敗與失追分開處理。

## 5. 狀態、時鐘與公平性

主要流程：首頁 → 載入／授權 → 校正 → 倒數 → 遊玩 → 結算。錯誤可重試或回首頁；遊玩中可手動暫停、失追暫停或頁面隱藏暫停。

- 用單調時鐘累計有效遊玩時間；暫停與倒數不計入。
- 暫停時凍結障礙、判定窗、無敵及關卡時間，背景影片一起暫停。
- 手動暫停不因追蹤恢復而自動解除；切回頁面也需明確恢復。
- 失追恢復且穩定後先倒數，清除舊事件再繼續。
- 中斷橫跨判定窗的題目取消判定並重新預告，不計成功、失敗或分數，避免恢復後立即扣血。
- 影片循環與緩衝不重設遊戲時鐘；背景不能播放時，先重試或明確選擇程式背景備援再開始。
- 重開清空生命、分數、障礙、時鐘與動作歷史；站位或鏡頭改變需重新校正。
- 離開時停止攝影機並釋放推論、動畫與事件監聽。

## 6. 校正與動作判定

### 校正流程

1. 以 `facingMode: 'user'` 偏好前鏡頭，只要求影像、不要求麥克風；鏡頭不符時清楚提示。
2. 顯示鏡像預覽及骨架，確認頭、肩、髖、膝與腳踝等必要關節可信且沒有貼近畫面邊界。
3. 收集穩定站姿，用中位數建立身體高度、軀幹尺度、髖中心與地面基準。
4. 引導左右跨步、蹲低與跳躍，確認能和站姿區分，記錄可追蹤範圍。
5. 顯示活動界線；缺關節或幅度不足時提示調整距離、光線或重試，不假通過。
6. 提醒家長確認安全空間；可追蹤範圍不等於實際環境安全。

左／右統一定義為玩家自身左／右，模型原始座標只在輸入邊界轉為鏡像互動座標；提示、骨架與判定共用此規則。以不對稱姿態資料及實機指令驗證，避免重複翻轉。

### 初始辨識策略

| 動作 | 主要訊號 | 防誤判與重新待命 |
| --- | --- | --- |
| Jump | 相對站姿的髖部上升、上升趨勢及腳部訊號 | 多筆有效取樣，排除僅伸手或抖動；落地回到基準後重啟 |
| Duck | 髖與肩下降，輔以膝部彎曲 | 穩定維持才成立，站回基準後重啟 |
| Dodge | 髖中心向指定方向平移 | 分清左右、排除只移動手部；回中央後重啟 |

採相對身體尺度與校正範圍，不用固定像素。濾波、品質、位移、持續時間、回正與冷卻參數集中設定，各動作可分別調校。跳躍是可玩性估計，不宣稱精密量測離地高度。

### 判定契約

- 初始判定窗為碰撞前 0.6 秒至碰撞時間；可依動作調整。
- 使用動作事件時間戳判斷是否落在窗內；窗外事件不留給下一題。
- 以進入動作及回正重新待命避免一直蹲著或偏左連續過關。
- 單一事件最多供一題使用，每題只結算一次。
- 到窗結束仍未成功且追蹤有效才算失敗；追蹤無效先暫停，不把缺資料當失敗。
- 無敵期間的失敗仍記一次失敗，但不再扣血，不算成功。
- 原型建議成功一題 100 分、失敗不加分；最多三心，不補血，零生命立即結算。
- 事件、判定窗與無敵採同一遊戲時間尺度，防止暫停後錯位。

## 7. 顯示與瀏覽器限制

- Video 置底，Canvas 畫障礙及輪廓，DOM 顯示生命、分數、追蹤及控制。
- 障礙與提示共用接近進度，遠小近大；視覺縮放不更改人體動作門檻。
- 障礙位置、尺寸與接地點共用透視模型及固定虛擬前進速度，不以各自獨立的 easing 放大。背景與 Canvas 共用同一 16:9 內容座標及縮放／留邊轉換，避免響應式裁切使道路錯位。
- 預覽隱藏僅改顯示，不停止辨識。Debug 顯示渲染／推論 FPS、推論耗時、關節、判定與障礙狀態。
- 影片使用 `muted`、`loop`、`playsinline`，由開始操作啟動並處理 `play()` 拒絕。參考：[MDN 自動播放指南](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)。
- 影片固定 `playbackRate = 1.0`；`loop` 屬播放設定，不代表已通過無縫循環驗收。影片 `currentTime` 只用於播放除錯，不當成遊戲時鐘。影片本身不含玩法障礙、角色、文字、UI 或動作提示。
- 攝影機需安全來源及使用者授權；區分拒絕、無鏡頭、占用、限制不符等錯誤。手機區網 HTTP 不等同 localhost。參考：[MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)。
- 全螢幕由點擊觸發，偵測支援與拒絕並提供 CSS 滿版；不保證隱藏瀏覽器工具列或鎖定橫向。參考：[MDN Fullscreen API](https://developer.mozilla.org/en-US/docs/Web/API/Fullscreen_API)。
- 直向提示旋轉但保留可操作介面；按鈕支援觸控與鍵盤，提示用圖形搭配文字，不只靠顏色。
- 攝影機畫面與人體資料不保存、不上傳；預設不建立兒童影像資料集。

## 8. 集中參數

| 參數 | Phase 1 起始值 |
| --- | --- |
| 起始生命／上限 | 3 |
| 扣血無敵 | 1.5 秒，暫停凍結 |
| 判定窗 | 碰撞前 0.6 秒，可依動作調整 |
| 障礙預告 | 3 秒 |
| 題目間隔 | 3～5 秒；原型固定題序涵蓋三動作及左右 |
| 原型時長 | 60 秒，獨立於正式關卡參數 |
| 開始／恢復倒數 | 3 秒，規劃預設 |
| 成功得分 | 100 分／題，規劃預設 |
| 姿態推論目標 | 15～20 FPS，不重複推論同一影格 |
| 渲染目標 | 60 FPS，待實機量測 |
| 校正與追蹤門檻 | P1-02～04 訂定，包含品質、穩定時間、失追、位移與回正 |

後續保留：連續 10 次成功補血、最近 10 次有效判定調整難度、一般關卡 45 秒、Boss 60 秒；Phase 1 不啟用。追蹤失敗不計入動態難度失敗率。背景保持固定速度，難度優先調整出題間隔、動作組合、姿勢複雜度與安全範圍內的密度，不直接加速背景；若未來改障礙接近速度，須另驗證運動衝突。

## 10. 測試與驗收

### 自動化

| 層級 | 關鍵案例 |
| --- | --- |
| 動作單元測試 | 正常／錯誤動作、單影格雜訊、身形尺度、缺關節、鏡像左右、持續姿態、未回正、過期資料 |
| 遊戲單元測試 | 判定窗邊界、窗外事件、事件重用、一次結算、無敵扣血、零血、時間到、同時碰撞與結束的固定順序 |
| 暫停測試 | 時鐘／無敵凍結、失追不扣血、清除舊事件、中斷題目重新預告、手動暫停不自動解除 |
| E2E | 首頁→模擬校正→挑戰→結算→重開；拒絕權限、模型／影片失敗、暫停、滿版替代、預覽切換 |
| 部署檢查 | 正式建置在 `/shape-quest/` 下可讀取 JS、影片、模型、WASM，檔案回應及 MIME 正確 |

合成姿態注入只用於測試，不讓正式玩家開啟假成功模式。Playwright 模擬鏡頭與姿態只能證明流程，不能證明真實動作精確度。Phase 2 再擴充完整姿態影格重播；如需真人資料，另訂同意與去識別流程。

### Phase 1 實機清單

- [ ] 至少一台手機、一台平板，於正式 HTTPS 網址完成約一分鐘遊玩。
- [ ] Jump、Duck、左 Dodge、右 Dodge 都能成功；錯方向、靜止與一直維持動作不能持續過題。
- [ ] 身體超出畫面、遮擋或不穩定會提示，校正可重試。
- [ ] 障礙與輪廓同步透視縮放，成功與失敗回饋明確，縮放不改變人體幅度。
- [ ] 首支正式候選背景沒有非預期玩法障礙，維持三線道與恰好兩條內部分隔線，消失點、天空與極遠地景穩定，Canvas 接地、速度感及縮放一致；完整原片約 0.333 秒離線淡化後，循環接點與 90～120 秒實際遊玩通過人工及實機驗收。
- [ ] 背景固定 1.0x 且靜音，暫停／恢復同步；不同畫面比例下道路 Overlay 與影片共用座標，播放失敗可重試或使用明確備援。
- [ ] 離開鏡頭、遮擋、切換頁籤不造成不公平扣血；恢復倒數後不立即碰撞。
- [ ] 三心、無敵、分數、成功／失敗數、Game Over、時間到與重開正確。
- [ ] 預覽切換不停止辨識，全螢幕或 CSS 滿版可操作，橫直向介面可用。

## 11. CI/CD 與 GitHub Pages

1. PR 與 push 至 `main` 執行 `npm ci`、型別檢查、Vitest、建置、Playwright 正式預覽測試。
2. CI 的 Node 與本機一致；安裝 Chromium 與所需依賴。
3. 任一檢查失敗即停止；PR 僅驗證，只有 main push 通過後上傳並部署 `dist/`。
4. 使用 GitHub 官方 Pages actions，實作時核對版本；部署設定 concurrency，避免舊版本覆蓋新版本。
5. 建置權限 `contents: read`，部署加入 `pages: write`、`id-token: write` 及 `github-pages` environment。
6. 維護者於 Settings → Pages 選 GitHub Actions，確認組織政策與環境保護規則允許。
7. Vite `base` 設 `/shape-quest/`；公用資源依 `import.meta.env.BASE_URL` 組路徑，打包資源使用 Vite 可解析的匯入，避免根路徑硬編碼。
8. 預期網址 `https://qqboxy.github.io/shape-quest/`；實際部署及驗證後才標示上線。自訂網域或 Repository 改名須重查 base。

依據：[Vite 靜態部署與 GitHub Pages](https://vite.dev/guide/static-deploy.html#github-pages)。已建立 .github/workflows/deploy.yml，尚未執行遠端工作流程或取得部署成功紀錄；權限不足時提供維護者設定步驟，不宣稱完成。

### 製作順序與關卡範圍

素材製作與遊戲 Phase 分開追蹤；既有 `l03_candy_001` 等素材 ID 保留，不代表世界必須按編號依序遊玩。

1. **場景規劃**：依各世界主題與共用規格安排道路、中近景及穩定遠景，避免迎面接近的終點地標。
2. **靜態圖片生成與驗收**：先確認美術、16:9、固定視角、三線道／兩條分隔線、中央淨空與景深；未通過不生成影片。
3. **Google Flow 影片生成與原片驗收**：依核准參考圖與共用 Prompt 生成，檢查前進動態、道路及遠景；不因首尾不完全一致直接淘汰。
4. **FFmpeg 淡化後製與循環驗收**：保留完整來源，確認實際 FPS／影格數，離線合成約 0.333 秒首尾淡化，輸出無音軌 H.264／yuv420p／faststart；原片與衍生檔分開保存，後製應能批次自動化。
5. **遊戲整合**：驗證道路對齊、Game Clock 獨立、暫停／恢復、90～120 秒播放、MediaPipe 同時運作、手機／平板及電視投放。未測項目明列待驗證。
6. **景觀擴充**：每個場景獨立驗收，不對已核准素材反覆生成。跨片切換品質另外驗證；單片首尾淡化不保證不同影片自然銜接。

幾何 Debug Overlay、測試與效能量測功能持續保留。影片循環不得重設 Game Clock、障礙物排程或姿態辨識，也不得中斷獨立播放的背景音樂。

剪輯後淡化僅保留比較與備選；複雜速度模糊、傳送門及雲霧轉場暫停開發；固定遠景＋程式近景混合渲染不作為目前正式方向。既有 PoC、量測與素材保留，以實際遊玩的自然度與舒適度驗收，不要求數學上完全無縫。

尚待驗證：正式遊戲預設背景、新淡化影片獨立 120 秒長測、各世界統一 Profile、跨片切換、行動裝置搭配 MediaPipe 效能與電視投放／兒童實玩。

### 素材登記與路徑

沿用可追溯的素材 ID，例如既有 `l03_candy_001_v2.mp4` 與對應參考圖；新場景須記錄世界、場景及版本。逐片記錄 ID、世界、場景、實際片長、比例、影片與參考圖、Profile 版本、音軌、循環策略、來源／授權及驗收結果。

歷史 v1.0 Metadata 的 `/videos/...`、`/references/...` 是示例素材位置；實作需轉為依 `import.meta.env.BASE_URL` 解析的相對資源路徑，支援 `/shape-quest/`，不可直接把示例根路徑當正式網址。未完成的 Profile 不得僅憑範例字串宣稱已存在。

製作流程狀態依序為 Draft → Reference Approved → Generated → Visual Passed → Integration Passed → Approved。Manifest 的發布資格另記 `candidate`／`approved`／`rejected`：整合通過前維持 candidate，有不可接受問題標 rejected，全部必要驗收通過才標 approved。正式關卡只使用 approved 素材；測試候選素材須清楚標示。目前正式背景整合與統一 Profile 尚未完成驗收，不因製作方向已確認而自動將候選素材標記為 approved。

### 音訊與後續擴充

正式衍生背景影片須移除音軌，播放器仍強制靜音；原始來源保留不覆寫，互動特效由遊戲事件產生。後續獨立音樂／音效系統需支援音量、暫停及事件觸發，不依影片時間判定動作，也不因景觀切換中斷音樂；正式音訊仍依原計畫留後續階段。

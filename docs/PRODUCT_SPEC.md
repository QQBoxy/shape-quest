# Shape Quest（奇形狀）— Codex 開發規格

> 本文件保留產品原始需求。背景製作、循環、世界規劃與整合方式以 [背景影片統一製作與整合規格 v2.0](BACKGROUND_VIDEO_SPEC.md)（2026-11-01）為最新依據；製作規格已確認，正式整合與裝置驗收仍待完成。

## 一、專案目標

- **中文名稱**：奇形狀
- **英文名稱**：Shape Quest
- **GitHub Repository**：`shape-quest`
- **遊戲類型**：兒童體感跑酷冒險
- **部署平台**：GitHub Pages

開發一款兒童體感跑酷網頁遊戲，將 Brain Break 跑酷影片轉變為透過身體動作即時互動的遊戲。

遊戲採第一人稱視角自動向前奔跑，以 HTML5 Video 播放背景影片，並透過 Canvas / WebGL 產生逐漸接近的障礙物與動作提示。

使用 MediaPipe Pose Landmarker 透過裝置前鏡頭辨識玩家全身動作，判斷是否成功避開障礙物。

### 核心原則

- 完全純前端，不建立後端、資料庫或帳號系統。
- 使用 GitHub 管理原始碼，透過 GitHub Pages 部署。
- 適合兒童，娛樂性優先，不要求專業級姿勢精確度。
- 支援手機、平板，以及透過螢幕鏡像投放電視遊玩。
- 使用授權影片或自行產生的原創動畫作為背景。
- 不使用 YouTube 影片、音訊或播放器。
- 採分階段開發，先完成可玩原型，再擴充完整遊戲。

## 二、技術架構

- TypeScript + Vite
- MediaPipe Tasks Vision（Pose Landmarker）
- Canvas 2D，必要時使用 PixiJS / WebGL
- HTML5 Video
- localStorage
- Vitest
- Playwright
- GitHub Actions + GitHub Pages

不引入不必要的前端框架或後端服務。

### 部署要求

- 使用 GitHub Actions 自動建置及部署 GitHub Pages。
- Push 至主要分支後自動測試、建置及部署。
- 測試及建置通過後才部署。
- 正確設定 Vite `base`，支援 GitHub Pages 專案子路徑。
- 靜態資源路徑須相容 GitHub Pages。
- 使用 HTTPS 存取攝影機。
- README 提供本機啟動、測試、建置及部署說明。
- 未取得必要權限時，提供設定步驟，不得宣稱部署成功。

## 三、遊戲核心玩法

### 基本流程

1. 進入 Shape Quest 主畫面。
2. 選擇全螢幕及遊玩模式。
3. 開啟前鏡頭並進行全身校正。
4. 倒數開始遊戲。
5. 第一人稱畫面持續向前奔跑。
6. 障礙物從遠方逐漸接近。
7. 動作提示輪廓與障礙物同步放大。
8. 玩家在判定時間窗內完成指定動作。
9. 成功通關或失敗扣血。
10. 挑戰各個關卡，最後顯示結算畫面。

### 動作庫

| 動作 | 對應障礙物 | 判定方式 |
|---|---|---|
| Jump | 地面方塊、坑洞 | 身體向上跳躍 |
| Duck | 懸空橫木 | 身體蹲低 |
| Dodge | 左右路障 | 向指定方向跨步 |
| Hole in the Wall | 人體姿勢牆 | 比對指定姿勢 |
| Smash | 可破壞牆壁 | 連續出拳 |

不需要辨識 Run 原地跑步，畫面始終自動前進。

Hole in the Wall 包含六種姿勢：

- T 字站姿
- 側面弓箭步舉手
- 雙手打開、單腳抬膝
- 雙臂 L 型上舉
- 身體側彎伸展
- 單腳站立瑜珈樹式

支援適當的左右鏡像變化。

### 動作判定

- 採用判定時間窗，不要求碰撞瞬間姿勢完全正確。
- 不同動作可以設定不同判定時間。
- 使用校正後的相對關節位置及時間序列分析。
- 姿勢辨識允許合理誤差。
- 避免單一影格誤判。
- 避免持續維持同一動作而重複通關。
- 追蹤失敗時暫停判定及扣血。
- 統一鏡像畫面與左右方向的座標定義。

## 四、攝影機校正

遊戲開始前必須進行校正：

1. 顯示鏡像攝影機畫面及人體骨架。
2. 確認玩家全身入鏡。
3. 建立站立高度、身體比例及中央位置基準。
4. 測試左右跨步範圍。
5. 測試深蹲及跳躍是否正常追蹤。
6. 顯示左右活動界線及可追蹤範圍。
7. 提醒玩家確認周圍有安全活動空間。

遊戲進行中：

- 預設隱藏攝影機畫面。
- 可切換左下角攝影機小視窗。
- 隱藏畫面後仍持續辨識人體。
- 顯示追蹤狀態。
- 追蹤異常時自動暫停，恢復後倒數繼續。

鏡頭可追蹤範圍不代表實際環境安全，仍須提醒家長確認。

## 五、影片背景與障礙物

### 背景影片

- 使用 HTML5 Video。
- 支援 MP4 循環播放。
- 使用有適當授權的影片或自行產生的原創動畫。
- 背景影片可以替換。
- 遊戲時間軸與影片時間軸分離。
- 不依賴後端影音服務。
- 開發時可使用示範影片或程式生成的動態背景。

### 障礙物

- 使用 Canvas / WebGL 即時產生。
- 從遠方逐漸接近玩家。
- 障礙物與指定動作提示輪廓同步放大。
- 模擬第一人稱透視及穿越效果。
- 成功時顯示避開、穿越或破壞動畫。
- 失敗時顯示碰撞效果。
- 動作提示應清晰易懂，避免背景干擾。

畫面上的動作輪廓放大，不應改變玩家實際需要完成的動作幅度。

## 六、智慧隨機與動態難度

### 智慧隨機

- 五大動作採加權隨機出題。
- 避免連續過多高強度動作。
- 左右方向盡量平衡。
- 複雜姿勢後保留恢復時間。
- 避免不合理的連續動作。
- 維持不可預測性。

### 動態難度

根據玩家近期有效動作判定成功率調整：

- 障礙物接近速度。
- 障礙物出現間隔。
- 姿勢複雜度。
- 題目出現機率。

連續成功提高難度；連續失敗降低難度。

追蹤失敗不得計入玩家失敗率。

設定速度、動作間隔與難度上下限。

## 七、生命值與關卡

### 生命值

- 預設三顆愛心。
- 動作失敗扣一顆。
- 扣血後有短暫無敵時間。
- 生命值以單一整數計算：上限 9 點，每顆愛心 3 點；成功補 1 點、失敗扣 3 點，限制在 0～9 點。愛心直接依生命值以三段填滿顯示，剩 1、2 點仍可遊玩，0 點才結束。
- 生命歸零時 Game Over。
- 顯示成功次數、失敗次數、分數及重新開始選項。

### 關卡結構

| 關卡 | 內容 |
|---|---|
| Level 1 | Jump、基本姿勢穿牆 |
| Level 2 | 新增 Duck |
| Level 3 | 新增 Dodge |
| Level 4 | 新增 Smash |
| Level 5 | 全動作混合 |
| Boss Level | 高強度全動作挑戰 |

關卡決定可用動作與主題，動態難度系統調整實際節奏。

每關約 30～60 秒，可透過設定調整。

## 八、使用者介面與裝置支援

- 響應式介面，支援手機、平板及桌面瀏覽器。
- 優先使用橫向畫面。
- 開始前提供全螢幕按鈕。
- 不支援 Fullscreen API 時使用 CSS 滿版替代方案。
- 支援手機／平板直接遊玩。
- 支援螢幕鏡像投放電視。
- 文字及動作提示適合電視觀看。
- 顯示生命值、分數、關卡及追蹤狀態。
- 支援暫停、繼續及重新開始。
- 介面簡單，適合兒童操作。

需考慮手機瀏覽器全螢幕限制及電視投放延遲。

## 九、建議初始參數

所有參數集中管理，不得分散硬編碼。

| 參數 | 初始值 |
|---|---|
| 生命值 | 9 點（三顆愛心，每顆 3 點） |
| 成功補血／失敗扣血 | ＋1 點／－3 點 |
| 扣血無敵時間 | 1.5 秒 |
| 基礎動作判定窗 | 碰撞前約 0.6 秒 |
| 障礙物預告 | 約 3 秒 |
| 障礙間隔 | 約 3～5 秒 |
| 一般關卡時間 | 45 秒 |
| Boss 關卡時間 | 60 秒 |
| 動態難度評估 | 最近 10 次有效判定 |
| 姿態辨識目標 | 15～20 FPS |
| 遊戲渲染目標 | 60 FPS |

實際參數依實機測試調整。

## 十、分階段開發

### Phase 1：可玩體感原型

實作：

- Shape Quest 主畫面與全螢幕按鈕。
- 攝影機及 MediaPipe 初始化。
- 全身入鏡與動作校正。
- Jump、Duck、Dodge 三種動作。
- HTML5 Video 背景。
- 障礙物與動作提示逐漸放大的動畫。
- 判定時間窗。
- 基本生命值、結算及重新開始。
- Debug 模式與單元測試。
- GitHub Pages 自動部署。

驗收：

- 可以在手機或平板連續遊玩約一分鐘。
- 三種動作能正常觸發。
- 障礙物與提示有遠近透視效果。
- 成功與失敗有不同回饋。
- 追蹤異常不造成不公平扣血。
- 可透過 GitHub Pages HTTPS 網址啟動遊戲。

### Phase 2：完整動作辨識

實作：

- Hole in the Wall 六種姿勢。
- 左右鏡像姿勢。
- Smash 連續出拳。
- 各動作獨立判定參數。
- 姿態影格重播測試。

驗收：五大動作皆可正常遊玩並有合理容錯。

### Phase 3：完整關卡系統

實作：

- Level 1～5。
- Boss Level。
- 智慧隨機出題。
- 動態適應難度。
- 累積成功補血與愛心填滿進度。
- 完整計分及結算。

驗收：可完成所有關卡，出題符合安全與恢復時間限制。

### Phase 4：裝置與效能最佳化

實作：

- 手機、平板相容性。
- 電視投放測試。
- 攝影機顯示切換。
- 全螢幕及畫面比例。
- 暫停及恢復。
- MediaPipe 效能優化。
- 背景影片替換。
- localStorage 保存設定及成績。

驗收：主要目標裝置可以穩定完成所有關卡。

### Phase 5：正式版本與視覺打磨

實作：

- 音效及動作回饋。
- 視覺特效與動畫優化。
- 兒童友善介面。
- 影片及音樂素材管理。
- 畫面與遊戲節奏調整。
- 正式版測試及 GitHub Pages 發布。

驗收：不需後端，可透過正式網址完整遊玩。

## 十一、程式品質要求

1. 模組化設計，避免大型單體程式。
2. 姿態辨識、動作判定、遊戲狀態與渲染分離。
3. 遊戲使用獨立且可暫停的時間軸。
4. 動作判定盡可能使用可單元測試的純函式。
5. 支援模擬姿態資料進行測試。
6. 避免 MediaPipe 推論阻塞動畫，必要時評估 Web Worker。
7. Debug Overlay 顯示 FPS、推論時間、關節位置、判定結果及障礙物狀態。
8. 所有遊戲參數集中管理。
9. 攝影機畫面及人體資料不得傳送到伺服器。
10. 每階段完成後執行測試及可玩性驗收。
11. 不得僅以自動化測試宣稱完成實機驗證。
12. 不得為未實作功能顯示假成功狀態。
